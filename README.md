# ForgeIQ
### AI Manufacturing Quality Intelligence

> **Predict defects. Understand causes. Optimize production.**

ForgeIQ is a full-stack, multi-agent AI decision-support platform for manufacturing quality intelligence. It continuously monitors simulated process telemetry across industrial machine lines, detects threshold/rule-based anomalies, predicts defect risk using a mathematical surrogate model, traces root causes through a causal workflow, retrieves grounding context from a keyword-based knowledge base, simulates virtual process recipe adjustments, and enforces Human-in-the-Loop operator sign-off before any parameter changes are accepted.

> ⚠️ **Demo & Simulated Environment**
> All telemetry, machine readings, quality scores, and production statistics in ForgeIQ are **simulated demo data** generated by an in-process Python simulation engine. ForgeIQ is not connected to real industrial hardware, OPC-UA endpoints, or MQTT brokers. All documents in the knowledge base are demo-authored representations of industry standards, not official ISO/DIN publications.

---

## Problem Statement

Manufacturing quality control traditionally relies on reactive, end-of-line inspection. Defects are discovered after parts are already produced, creating scrap waste, rework costs, and missed SLA targets. ForgeIQ demonstrates an architecture for AI-driven **proactive** defect prevention — catching quality risks during production, not after.

---

## What ForgeIQ Does

1. **Simulates a 12-machine factory** across 4 production lines (Stamping, CNC Machining, Robotic Assembly, Metrology Inspection)
2. **Monitors simulated telemetry** (temperature, pressure, vibration, RPM, torque, humidity, and more) with stochastic drift simulation
3. **Detects anomalies** using rule/threshold-based evaluation against configurable control limits
4. **Predicts defect risk** via a multi-factor mathematical surrogate model (sigmoid-weighted linear combination of sensor deviations)
5. **Retrieves relevant context** from a demo knowledge base using token/keyword-based relevance matching
6. **Generates process recommendations** grounded in retrieved knowledge excerpts
7. **Requires human operator approval** before any recommended parameter change is applied
8. **Provides natural-language Copilot** responses — with optional Groq LLaMA-3.3-70B LLM, or a deterministic rule-based fallback engine

## RAG / Knowledge Retrieval

The knowledge retrieval system in ForgeIQ uses **token/keyword-based relevance matching** — not semantic vector embeddings or dense retrieval:

1. **Query tokenization**: Query text is split into lowercase alphanumeric tokens
2. **Token intersection scoring**: Jaccard-like overlap between query tokens and chunk tokens
3. **Keyword boost**: Extra score weight when explicit keywords in a chunk match query tokens
4. **Top-K ranking**: Results sorted by composite relevance score

> **Accurate description:** "Knowledge retrieval using token/keyword-based relevance matching."
> This is **not** semantic vector search, vector embeddings, or cosine similarity over dense embeddings.

## AI / ML Approach

### Defect Prediction (Surrogate Model)
- **Algorithm**: Multi-factor linear combination with sigmoid squash
- **Inputs**: Temperature, vibration, hydraulic pressure, RPM (normalized deviations from baseline)
- **Output**: Defect probability [0, 1] + risk classification (NORMAL / EARLY WARNING / HIGH RISK / CRITICAL)
- **NOT**: RandomForest, IsolationForest, SHAP, or any trained/fitted scikit-learn estimator
- **Limitation**: Fixed coefficients, not data-driven; output is a demo approximation

### Anomaly Detection (Rule-Based)
- **Algorithm**: Hard-threshold evaluation against configurable control limits (warning / critical bands)
- **Inputs**: Vibration, temperature, hydraulic pressure per machine
- **Output**: Structured anomaly objects with severity, deviation %, and explanation
- **NOT**: IsolationForest, statistical process control (SPC), or machine learning

### What-If Simulator (Mathematical Surrogate)
- **Algorithm**: Parametric equations estimating output deltas from input parameter changes
- **Inputs**: Temperature, pressure, RPM, feed speed, coolant flow
- **Output**: Estimated defect probability delta, quality score change, scrap rate, production time delta
- **Limitation**: Fixed surrogate relationships; not a physics simulation or trained ML model

### Forge Copilot (Conversational AI)
- **Primary mode**: Groq LLaMA-3.3-70B (when `GROQ_API_KEY` is set) — live LLM with RAG context injection
- **Fallback mode**: Deterministic rule-based response templates keyed on query intent
- **RAG grounding**: Retrieved knowledge chunks injected into LLM context

## Demo & Simulated Data Disclaimer

> 🔬 **All data in ForgeIQ is simulated for demonstration purposes.**

| Data | Reality |
|---|---|
| Machine telemetry | Generated by Python random-walk simulation, not real sensors |
| Defect probability | Computed by surrogate math formula, not a trained model |
| Quality scores | Heuristic estimates, not measured outcomes |
| Forge Quality Index™ (FQI) | Project-defined composite indicator for demo purposes; **not an industry-standard quality metric** |
| ISO/DIN document content | Demo-authored representations, not official standard publications |
| Incident reports (INC-2026-088) | Fictional demo scenario |
| Production counts, scrap rates | Seeded demo values, not real production data |
| "91% confidence" values | Fixed heuristic, not empirically validated accuracy metrics |

**Forge Quality Index™ (FQI)** is a project-defined composite indicator calculated from weighted heuristic sub-scores (process stability 25%, defect probability 20%, sensor health 15%, historical quality 15%, machine condition 15%, material consistency 10%). It is not an industry-standard quality metric.

## Local Installation

### Prerequisites
- **Python 3.12+**
- **Node.js 18+** and **npm**

### 1. Clone the repository

```bash
git clone https://github.com/your-username/forgeiqAI.git
cd forgeiqAI
```

### 2. Backend setup

```bash
cd backend
python -m venv .venv

# Activate virtual environment
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

### 3. Configure environment variables

```bash
# Copy the example env file
cp backend/.env.example backend/.env

# Edit backend/.env
# Optional: set GROQ_API_KEY for live LLM Copilot
# Leave blank to use deterministic fallback engine
```

### 4. Frontend setup

```bash
cd frontend
npm install
```

## Demo Workflow (8-Step Guided Tour)

Click **[START GUIDED DEMO]** in the sidebar to run the full 2–3 minute demonstration:

1. **Start Factory** — Resets all 12 machines to nominal golden baseline (simulated)
2. **Detect Anomaly** — Injects an 8.6 mm/s vibration spike on CNC-MILL #06 (simulated fault injection)
3. **Analyze Quality** — Quality Analysis Agent flags +3.82 sigma deviation and Cpk degradation (heuristic)
4. **Predict Defect** — Defect Prediction Agent computes 82% Dimensional Inaccuracy risk (surrogate model)
5. **Explain Root Cause** — Root-Cause Graph visualizes causal chain from bearing wear to thermal growth
6. **Run What-If** — Test lowering Spindle RPM 1780 → 1420 and boosting flood coolant to 100% (parametric estimate)
7. **Stage Recommendation** — Process Optimization Agent stages REC-401 for operator sign-off (Human-in-the-Loop)
8. **Approve & Restore** — Operator approves; simulated machine parameters update and quality score recovers

## Limitations

- **No real hardware connectivity**: No OPC-UA, MQTT, or real PLC integration
- **No trained ML models**: Defect prediction uses deterministic math formulas, not fitted classifiers
- **No vector embeddings**: RAG uses keyword token overlap, not semantic embedding search
- **No real standard documents**: All knowledge documents are demo-authored representations
- **In-memory only**: All state is lost on server restart (no persistent database)
- **Not production-validated**: Accuracy metrics (confidence %, Cpk values) are illustrative demo numbers
- **Groq API optional**: Without a `GROQ_API_KEY`, Copilot uses a fixed rule-based response engine
